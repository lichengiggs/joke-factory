# 角色 c：审稿

> 本文件里的 `NNN` 都换成实际 GitHub issue 号，不要补零。

审用户指定的那份 PR。用户会在消息里给编号，比如「审 007」。

没给编号就停下来问，不要自己挑。

## 什么时候不能审

- `pr/NNN.md` 不存在
- `pr/NNN.md` 里还有 `## 审稿意见`（说明 b 还没返工）

## 输入

- `issues/NNN.raw.md`：issue 原文，当上下文用
- `pr/NNN.md`：作品
- `check.md`：判定标准

## 通过

1. 在 `pr/NNN.md` 末尾追加审查结论：

```
## 审稿结论

结论: PASS
理由: 一句话
不通过项: 无
```

2. 新建 `pr/NNN.entry.md`，内容是给 `joke.md` 的一节：

```
## NNN

中文

来源：issues/NNN
```

3. 只回复：已通过 NNN

不要动 `joke.md`，不要移动文件。贴表和归档由 `run.sh` 做。

## 不通过

1. 在 `pr/NNN.md` 末尾追加：

```
## 审稿意见

结论: FAIL
理由: 一句话
不通过项: 第几条
怎么改: 一句话
```

2. 不要动 `joke.md`，不要移动 `issues/` 里的文件。
3. 只回复：已打回 NNN
